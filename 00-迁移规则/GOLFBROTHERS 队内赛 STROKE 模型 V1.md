# 《GOLFBROTHERS 队内赛 STROKE 模型 V1》

版本：V1.0  
适用范围：

- 队内赛
- 比杆赛体系
- G1/G2/G3/G4

暂不包含：

- G5-G8 比洞赛
- 队际赛

---

# 1. 设计目标

当前系统已经基于：

> G1 个人比杆赛

建立了稳定的：

- 成绩录入
- scoreData
- leaderboard
- 记分页面

下一阶段扩展目标：

在不破坏 G1 的基础上，引入：

- 组合成绩模型；
- 分队驱动的组合生成；
- 组合规则校验；
- LIVE阶段换人安全机制。

核心原则：

> 比赛成绩必须基于稳定的成绩实体（Score Entity）产生，而不是页面临时计算。

---

# 2. Stroke成绩实体模型

队内赛比杆赛共有三类成绩实体：

```
Score Entity├── Player Entity│├── Group Entity│└── Pair Entity
```

---

# 3. G1 个人比杆赛模型

## UI名称

个人比杆赛

## 内部模型

```
Player Stroke
```

---

## 成绩实体

```
Match Group↓Player Entity↓Score Fact
```

---

示例：

第一组：

```
张三李四王五赵六
```

生成：

```
Player Entity A张三Player Entity B李四Player Entity C王五Player Entity D赵六
```

---

特点：

- 一个球员对应一个成绩；
- 排名对象为个人。

---

# 4. G2/G3 Group Stroke模型

## 4.1 UI名称规范

### G2

统一：

> 最好成绩比杆赛

### G3

保持：

> 最佳球位比杆赛

---

不再使用：

❌ 四人四球比杆赛  
❌ 四人四球最好成绩比杆赛

原因：

G2内部并不限定：

- 必须4人；
- 必须两队；
- 必须固定组合人数。

---

# 4.2 G2/G3内部统一模型

二者均属于：

```
Group Stroke
```

区别：

| 赛制         | 成绩规则           |
| ---------- | -------------- |
| G2 最好成绩比杆赛 | 组合成员中取最佳成绩     |
| G3 最佳球位比杆赛 | 按照最佳球位规则产生组合成绩 |

---

数据结构：

```
Match Group↓Group Entity↓Score Fact
```

---

# 5. G2/G3组合生成规则

## 5.1 不增加创建参数

创建页面：

选择：

```
最好成绩比杆赛
```

或：

```
最佳球位比杆赛
```

后：

不要求用户选择：

- 4+0
- 2+2
- 2+1

---

原因：

这些属于实际分组结果，而不是比赛配置。

---

# 5.2 合法组合结构

G2/G3支持两类组合结构。

---

## 类型A：单分队组合

定义：

一个比赛组内：

所有球员来自同一个分队。

例如：

```
红队：R1R2R3R4
```

生成：

```
Group EntityR1/R2/R3/R4
```

---

允许缺员：

```
R1R2
```

或者：

```
R1
```

仍然合法。

---

## 类型B：双分队组合

定义：

一个比赛组内：

存在两个分队。

每个分队：

最多2人。

---

合法：

### 2+2

```
红：R1R2蓝：B1B2
```

---

### 2+1

```
红：R1R2蓝：B1
```

---

### 1+2

```
红：R1蓝：B1B2
```

---

### 1+1

```
红：R1蓝：B1
```

---

# 5.3 G2/G3禁止结构

## 超过两个分队

例如：

```
红：R1 R2蓝：B1白：W1
```

禁止。

---

## 双分队情况下单方超过2人

例如：

```
红：R1R2R3蓝：B1
```

禁止。

---

## 单分队超过4人

例如：

```
R1R2R3R4R5
```

禁止。

---

# 5.4 同一比赛组合方式必须统一

同一场比赛：

所有 Match Group 必须保持一致组合结构。

---

允许：

全部：

```
单分队组合
```

或者：

全部：

```
双分队组合
```

---

禁止：

第一组：

```
红：R1R2R3R4单分队组合
```

第二组：

```
红：R5R6蓝：B1B2双分队组合
```

---

保存分组时：

校验失败。

提示：

> 同一比赛内所有分组必须保持一致组合方式，请调整分组后重新保存。

# 7. G4分组规则

G4要求：

每个比赛组：

必须：

```
2人或者4人
```

---

禁止：

```
1人3人
```

---

# 7.1 两人情况

必须：

来自同一个分队。

合法：

```
红：R1R2
```

---

非法：

```
红：R1蓝：B1
```

---

# 7.2 四人情况

## 单分队球队

允许：

```
ABCD
```

生成：

```
Pair A:A+BPair B:C+D
```

---

## 多分队球队

必须：

来自两个不同分队。

合法：

```
红：R1R2蓝：B1B2
```

---

非法：

```
红：R1R2R3R4
```

（存在多个分队情况下）

---

# 8. 赛制修改规则

核心原则：

> 根据目标赛制验证当前分组，而不是根据旧赛制判断。

---

## 降级

无需校验：

例如：

```
G4 → G2/G3/G1G2/G3 → G1
```

---

## 升级

需要校验：

例如：

```
G1 → G2/G3G1/G2/G3 → G4
```

---

失败：

不进行局部修复。

统一提示：

> 当前分组不符合新赛制要求，如修改赛制将清除所有分组信息，请重新进行分组。

---

# 9. LIVE阶段规则

管理员点击：

```
开始比赛
```

状态：

```
报名中↓LIVE
```

---

LIVE后：

冻结：

- 赛制；
- 比赛分组；
- Score Entity 类型。

---

# 10. LIVE换人规则

## G1

个人替换：

```
A替换B
```

即可。

---

## G2/G3

换人后：

重新验证：

```
新的组合结构+G2/G3组合规则
```

---

允许：

组合人数变化。

例如：

原：

```
红：R1R2蓝：B1B2
```

换人后：

```
红：R1蓝：B1B2
```

合法。

---

禁止：

产生非法结构。

---

## G4

换人：

保持 Pair。

例如：

原：

```
R1 + R2
```

替换：

```
R1 + A
```

Pair不改变。

---

# 11. LIVE扫码加入规则

适用于：

G2/G3/G4。

---

## 已有分队属性

优先使用已有分队。

---

## 无分队属性

根据当前组合状态判断。

---

如果存在唯一合理补位：

自动加入。

例如：

当前：

```
红1蓝2
```

加入：

自动进入红。

形成：

```
红2蓝2
```

---

如果无法判断：

例如：

```
红1蓝1
```

要求选择：

```
请选择加入分队
```

---

# 13. 最终模型总结

```
队内赛 Stroke        Score Entity            |--------------------------------Player Entity        |        G1个人比杆Group Entity        |        G2最好成绩比杆赛        G3最佳球位比杆赛Pair Entity        |        G4四人两球比杆赛--------------------------------
```

---

## 当前阶段结论

G1-G4不是四个独立赛制。

而是三个成绩实体模型：

1. **个人成绩模型**
2. **组合成绩模型**
3. **双人球组模型**

其中：

G2/G3共享组合模型。

下一阶段代码开发重点：

> 在保持 G1 稳定运行的前提下，引入 Group Entity 和 Pair Entity。
