# 《GOLFBROTHERS G2/G3 Entity生成规则 V1》

版本：V1.0

适用：

- G2：最好成绩比杆赛
- G3：最佳球位比杆赛

不适用：

- G1个人比杆
- G4四人两球比杆

---

# 1. 基本原则

## 1.1 G2/G3系统模型相同

系统内部：

统一：

```
Group Stroke Entity
```

区别：

仅：

UI文案。

---

| 赛制  | 显示名称    | Entity       |
| --- | ------- | ------------ |
| G2  | 最好成绩比杆赛 | Group Entity |
| G3  | 最佳球位比杆赛 | Group Entity |

---

# 2. 核心约束

球队赛中：

G2/G3不允许用户手工创建组合。

组合由：

```
报名分队属性+管理员分组结果自动生成
```

---

原因：

避免：

- 组合配置复杂
- LIVE换人异常
- 分队关系丢失

---

# 3. Entity生成输入

生成时需要：

## 3.1 比赛组

来源：

```
match.groups
```

---

例如：

```
group001:

R1
R2
B1
B2
```

---

## 3.2 球员分队

来源：

```
registerInfo.users.groupId
```

---

例如：

```
R1 → 红队R2 → 红队B1 → 蓝队B2 → 蓝队
```

---

# 4. 模式判断

每个比赛组单独分析。

---

统计：

```
该组球员+所属分队
```

得到：

例如：

```
红队:2人蓝队:2人
```

---

形成：

```
teamDistribution
```

---

# 5. 合法组合模式

球队赛G2/G3：

允许：

## 模式A：4+0

单分队组合。

---

条件：

一个组：

所有球员来自同一个分队。

例如：

```
红:R1R2R3R4
```

---

生成：

一个Entity：

```
{ entityType:"group", members:[ R1, R2, R3, R4
 ]}
```

---

# 模式B：2+2

双分队组合。

---

条件：

两个分队。

每个分队：

最多2人。

例如：

```
红:R1R2蓝:B1B2
```

---

生成：

两个Entity：

```
Entity1:

R1,R2


Entity2:

B1,B2
```

---

# 模式C：2+1 / 1+2

双分队不满员。

---

允许。

例如：

```
红:R1,R2蓝:B1
```

---

生成：

两个Entity：

```
Entity1:

R1,R2


Entity2:

B1
```

---

注意：

单人Entity合法。

---

# 模式D：1+1

允许。

例如：

```
红:R1蓝:B1
```

---

生成：

两个Entity。

---

# 6. 禁止模式

---

## 6.1 多分队混合

禁止：

```
红:R1,R2蓝:B1白:W1
```

原因：

超过两个成绩主体。

---

提示：

统一：

> 当前分组不符合该赛制要求，请重新分组。

---

## 6.2 2+3

禁止。

原因：

G2/G3球队赛约束：

最多两个分队。

---

## 6.3 1+1+1

禁止。

---

## 6.4 3+1

建议：

禁止。

原因：

虽然高尔夫规则存在，

但系统复杂度增加。

---

统一：

允许：

```
4+02+22+11+21+1
```

---

# 7. 整场比赛组合模式约束

重要：

一次比赛只能存在一种模式。

---

例如：

合法：

所有组：

```
4+0
```

---

合法：

所有组：

```
2+2
```

---

非法：

第一组：

```
4+0
```

第二组：

```
2+2
```

---

保存失败。

提示：

> 当前比赛包含不同组合方式，请统一分组模式。

---

# 8. 模式识别

系统生成：

```
match.strokeEntityMode
```

---

例如：

```
{ type:"group",

composition:"4+0"
}
```

---

或者：

```
{
type:"group",

composition:"2+2"
}
```

---

用于：

- 校验
- 展示
- LIVE换人

---

# 9. Entity ID规则

Entity生成后：

固定。

---

例如：

```
{
entityId:"group001-teamA"
}
```

---

不要：

根据成员生成。

错误：

```
R1_R2
```

原因：

换人会改变ID。

---

正确：

基于：

```
matchId+groupId+序号
```

---

# 10. LIVE换人规则

## 原则：

Entity不变。

成员变化。

---

例：

原：

```
红:R1,R2蓝:B1,B2
```

Entity：

```
E1:R1,R2E2:B1,B2
```

---

换：

R2 → B3

结果：

```
E1:R1,B3E2:B1,B2
```

---

注意：

这里是否允许跨Entity移动，需要结合LIVE规则。

第一版建议：

允许替换，不重新拆Entity。

---

# 11. 单分队情况下特殊规则

如果球队只有一个分队：

G2/G3：

不要求2人组合。

---

例如：

8人：

```
A1-A8
```

分四组：

```
A1-A4A5-A8
```

自动：

每组一个Entity。

---

不询问：

4+0还是其他。

---

# 12. 与普通创建区别

普通创建：

用户主动选择：

- 最好成绩赛
- 最佳球位赛

并配置组合。

球队赛：

不配置组合。

由：

```
分队属性+分组结果↓自动生成Entity
```

---

# 13. 最终生成流程

```
管理员保存分组        ↓读取groups        ↓读取registerInfo分队        ↓统计每组分队人数        ↓判断4+0/2+2/2+1/1+1        ↓生成Group Entity        ↓保存scoreEntities        ↓进入LIVE
```

---

# 结论

G2/G3球队赛采用：

> “分队驱动的自动组合模型”。

不让管理员配置组合。

系统只校验：

- 分组是否满足规则；
- 全场组合模式是否一致。

这样：

- UI简单；
- LIVE安全；
- 换人可控；
- Entity稳定。
