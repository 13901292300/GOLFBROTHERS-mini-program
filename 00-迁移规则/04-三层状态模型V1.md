# 🧠 一、核心目标

统一所有“创建类页面”的状态管理，解决你现在遇到的：

- 文案丢失
- 轻量按钮消失
- scroll触发UI异常
- 弹窗影响主页面
- setData 状态污染

---

# 🚨 二、三层状态模型定义（核心）

## 🟡 1. Draft（编辑态）

> 用户正在操作的数据（未提交）

特点：

- 仅存在于弹窗 / 表单内部
- 可随意修改
- 不影响主页面

示例：

```
draftFeeListdraftTeamGroupsdraftEventInfo
```

---

## 🔵 2. Preview（预览态）

> 用于主页面“临时展示”的状态

特点：

- 可见
- 非最终
- 可随 draft 实时生成

示例：

```
feePreviewteamGroupPrevieweventInfoPreview
```

---

## 🟢 3. Commit（提交态）

> 最终保存状态（主页面唯一可信数据源）

特点：

- 唯一真源（Single Source of Truth）
- 影响广场 / 列表 / 后续逻辑

示例：

```
feeListteamGroupseventInfoList
```

---

# 🔁 三、状态流转模型（核心）

```
Draft  ↓（实时生成）Preview  ↓（confirm）Commit
```

---

# 🚨 四、关键原则（非常重要）

## ✔ 1. 主页面只能读 Commit + Preview

禁止：

- 直接读取 Draft

---

## ✔ 2. 弹窗只能写 Draft

禁止：

- setData 直接写 feeList / teamGroups

---

## ✔ 3. Preview 只用于 UI展示

例如：

- tag显示
- 费用展示
- 分队展示

---

## ✔ 4. Commit 只在 confirm 时更新

---

# 🎯 六、标准操作流程（必须统一）

## ✔ 打开弹窗

```
draft = deepClone(commit)
```

---

## ✔ 编辑过程中

```
draft → 自动更新 preview
```

---

## ✔ 取消

```
丢弃 draft不动 commit
```

---

## ✔ 确认

```
commit = draftpreview = commit
```

---

# 🧨 七、禁止行为（非常重要）

❌ 不允许：

- draft 直接影响 commit
- commit 被 scroll / UI 触发修改
- preview 和 commit 混用
- 用 hidden 控制状态替代 data

---

# 🚨 八、你当前 bug 的根本解释（关键）

你之前的问题本质是：

> ❗ commit 被 draft / UI 事件污染

或者：

> ❗ preview 没有存在，UI 直接依赖 commit

---

# 🧱 九、UI绑定规则（非常重要）

## 主页面只能绑定：

```
✔ preview（展示）✔ commit（数据）
```

❌ 禁止：

```
draft（绝对禁止）
```

---

# 🧪 十、验收标准

## ✔ 弹窗行为：

- 编辑不影响主页面
- 取消不影响数据
- confirm 才更新 commit

---

## ✔ 主页面：

- 文案不会消失
- 按钮不会消失
- scroll 不影响 UI
- 所有展示稳定

---

## ✔ 系统稳定性：

- 不再出现“时间组件恢复 UI”
- 不再出现“滚动后 UI 消失”
- 不再出现“弹窗污染主页面”
